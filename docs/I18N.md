# Traduction FR / EN — conventions

Le **français est la langue de référence** : chaque texte du code est écrit en
français et sert de clé. L'anglais vient de dictionnaires par module.

## Dans un composant

```jsx
import { useI18n } from '../../lib/i18n.jsx';

function MaPage() {
  const { tr } = useI18n();          // en tête du composant, avant tout return
  return <h1>{tr('Répertoire des localités')}</h1>;
}
```

- Variables : `tr('{n} unité(s) importée(s)', { n })` — mêmes `{noms}` dans la
  traduction. Les nombres passés en variable sont formatés selon la langue.
- **Chaque composant** qui appelle `tr` appelle lui-même `useI18n()` (les
  sous-composants d'un même fichier aussi). Une fonction utilitaire qui n'est
  pas un composant ne peut pas appeler de hook : elle reçoit `tr` en paramètre.
- Tables de constantes (statuts, rubriques…) : le libellé reste en français
  dans la constante et se traduit **à l'affichage** : `tr(def.label)`.
  `StatusBadge` et `RiskBadge` le font déjà.
- À traduire : textes JSX, `placeholder`, `title`, `aria-label`, messages de
  toast, `window.confirm`, en-têtes de colonnes, options de listes, états vides,
  en-têtes d'export CSV.
- À ne **pas** traduire : données venant de la base, codes, valeurs envoyées à
  l'API (clés de statut…), classes CSS, chemins.

## Dictionnaires

`web/src/locales/en/<module>.js` — clé = phrase française **exacte**. Les
phrases communes (Annuler, Enregistrer, Exporter…) sont dans `common.js`.
Une phrase absente reste affichée en français (aucune erreur).

## Contrôle de complétude

En développement, toute phrase demandée en anglais sans traduction est ajoutée
à `window.__memsMissingTr` ; un balayage Playwright des routes en anglais la
relève.

## Formats

`lib/format.js` suit la langue (`setFormatLocale`, appelé par `I18nProvider`) :
séparateurs de milliers, noms de mois, dates et heures.
